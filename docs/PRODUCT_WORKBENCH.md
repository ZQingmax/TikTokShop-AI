# 商品编辑工作台

入口：采集上架 → 我的采集箱 → 选择商品 → 进入商品编辑工作台。

## 使用流程

1. 选择目标店铺并保存。店铺来自已授权妙手账号，沿用 MY、TH、VN、SG、PH、ID 六个站点，语言默认 en。
2. 编辑标题、卖点、描述、商品图和人工确认的事实。图片第一张为主图；默认图片生成/编辑分辨率 1024x1024，图片翻译保留原图尺寸。
3. 分别提交文字识别、文案生成、图片生成、图片编辑或图片翻译。在 AI 结果中对比，再采纳或替换图片。AI 不自动覆盖手工内容。
4. 选择末级类目，映射销售规格和商品属性，生成 SKU 组合，填写销售价及仓库库存。来源采购价和货源库存仅用于对照。
5. 填写重量（kg）、包装尺寸（cm）及类目要求的真实资料。「检查草稿」显示距离可发布还缺哪些资料；缺失信息不会用样本或猜测值补齐。
6. 同步到妙手采集箱：选择店铺即可同步，首次同步把商品加入该店铺 TikTok 采集箱（采集/复用货源、认领平台箱、认领店铺、保存并回读），之后的同步编辑同一采集箱商品。未完成的字段本次跳过、妙手中保持原样，结果中列出。

每个货源商品只有一份草稿，目标店铺是草稿的属性，同步到该店铺前可以更换。妙手中直接修改过的商品会阻止覆盖，需在任务中确认「以草稿内容覆盖」。「删除草稿」把草稿从工作台移除（归档保留，不删除妙手中的商品）。来源采集箱商品移除后，已有草稿及快照继续保存。

## 启动与配置

- 在独立测试库验证迁移后，对实际业务库执行 `python -m alembic upgrade head`。
- 重启后端及 `python -m app.services.sourcing_worker`。该入口同时启动选品、采集、自动发现和工作台 Worker。
- 配置参考 `backend/.env.workbench.example`。百炼复用 BAILIAN_API_KEY / DASHSCOPE_API_KEY；妙手复用服务端应用凭证。模型和地域错误会显示实际错误状态。
- 若旧域名的 `/images/generations` 返回 404，设置 `WORKBENCH_IMAGE_BASE_URL` 为该业务空间的图片兼容地址；不会擅自更换 `qwen-image-3.0`。修改地址后需重启 Worker，并创建新任务，既有任务保留提交时的配置。
- 本地副本位于 WORKBENCH_ASSET_DIRECTORY，默认项目 `.runtime/workbench-assets`。将该目录作为持久化数据卷备份，不要在部署时清理。
- 图像校验需要 Pillow；已加入本地依赖列表。首版支持来源图片、加工图片和公网 URL，不支持本地文件上传。

## 接口与恢复

接口组 `/api/v1/product-workbench` 包含配置、草稿创建/查询/版本化保存、店铺/类目/仓库查询、检查、AI 任务、采纳、图片副本及同步恢复。API 路由通过角色和 owner_id 限制访问。

保存时传 version；冲突返回 409。每个任务使用唯一 request_key，相同请求重复提交返回原任务。检查结果绑定草稿版本，仅用于发布准备，不阻止同步。同步锁定提交版本，期间后续编辑显示「有未同步修改」。

任务在调用模型、转存图片、认领和保存前写入提交标记。模型结果、翻译任务 ID、本地副本和平台 ID 分步持久化。转存失败恢复时复用模型结果。未确认的模型调用需要人工确认可能再次计费；未确认的图片转存需要确认重新转存。已提交的商品保存只回读，不自动重复提交。

百炼临时图片 URL 到期前需要完成图片空间转存。若临时地址已过期且没有可访问的图片空间副本，保留本地图片，但转存任务无法凭本地路径恢复，需提供可访问的新图片地址。前端不会把服务端本地路径提交给妙手。

妙手保存使用 `detailId`、`shopId`、`ossMd5`、`shopCollectItemInfo`。SKU key 为排序后的属性值 ID 组合。远端变更冲突阻止覆盖，除非运营人员确认以草稿覆盖；只发送检查通过的字段（类目/属性/认证、规格/SKU、尺码表按组发送）；未通过回读检查不标记成功。详细描述有详情图时以生成的 HTML 发送，回读按规范化后的 HTML 比较。保存接口的 `deliveryOptionSetType=default` 不在文档 GET 示例中返回，因此回读核对其余受控字段。

旧 `/api/v1/collect-box/sync` 返回工作台指引。历史采集任务与同步结果继续可查询，底层货源采集能力继续用于新流程。

## 验证

- 独立 PostgreSQL `*_test` 库：`pytest tests unit_tests -q`。Windows 临时目录受限时指定项目 `.runtime` 下的专用 `--basetemp`。
- 数据库与模型一致性：`alembic check`。
- 前端：`npm run build`（包括 vue-tsc）。
- 显式真实模型测试：从 backend 运行 `python -m scripts.verify_workbench_real --box-id UUID --execute-ai`。默认只测试一次文字识别，付费调用预算 `--max-model-calls` 默认 1；多项测试必须显式指定操作及预算。脚本为该真实采集箱商品创建/复用未绑定草稿，生成候选结果，记录 request_id/usage/错误；不采纳结果或填造缺失上架字段。
- 真实商品同步需要运营人员确认售价、库存、包装尺寸和类目资料。真实验证与标注的测试夹具证据分别记录，不能把测试通过当作真实发布条件齐全。
