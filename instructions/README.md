## 当前架构和数据流

管理后台使用 Vue，业务 API 使用 FastAPI 和 PostgreSQL。`backend/app/services/sourcing_worker.py` 是组合任务入口，启动选品、采集、自动发现、工作台、发布与订单同步；FastMoss 使用独立本机 Worker。

`agent/` 中的 LangGraph / LangChain 服务和 `scraper/` 中的 Scrapy 实现是未接入当前后台主流程的历史模块。Redis 有依赖和客户端封装但没有业务调用；MinIO 只有依赖 / 配置，工作台图片使用本地副本及妙手图片空间。RabbitMQ / Celery 留有配置和旧物流任务，当前组合 Worker 使用 PostgreSQL 与 asyncio。Compose 中旧爬虫命令引用的 `scraper.tasks` 不存在，不能把 Compose 文件存在当作该服务已可用。详见 [README 组件状态表](../README.md)。

```text
FastMoss / 市场证据 / 手动货源 / 1688 CLI
  → 候选库 → AI 评估 → 人工审核
  → 我的采集箱 → 商品工作台 → 妙手店铺采集箱 → 预检与发布任务

妙手 TikTok 采集箱 / 包裹与采购单
  → 本地商品、订单与履约数据 → 仪表盘与财务汇总
```

步骤间有独立操作和任务，不代表审核后自动执行下一步。公共采集箱 ID、TikTok 采集箱 ID、店铺 ID 和本地草稿 UUID 分别保存。

## 状态与边界

- “已实现”表示存在代码，不等同于所有真实账号、站点或生产环境已验收。验收记录须有环境、日期、命令、结果和外部任务证据。
- 基础启动仍保留旧客服、TikTok、1688 模拟开关；独立来源与工作台使用自己的配置，不能用一个开关推断全部能力。
- FastMoss 当前抓取新品榜。榜单周期指标、货源库存和销量分别记录。
- 货源参考价、采购成本、店铺售价及人民币汇总各有口径，缺失值不能补造。
- 草稿同步和正式发布分开；采集、模型和发布的不确定结果使用各自恢复流程。
- 自动采购、付款、发货、完整结算对账和生产级无人值守不作为现有交付承诺。
- 权限以实际后端校验为准，部分旧模块仍需专项梳理，不能推定已具备完整细粒度 RBAC。
- 顶部外观入口为“太阳图标 + 主题”；五种主题在本机保存。退出清除本机会话并完整跳转登录页。
